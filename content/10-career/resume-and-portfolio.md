# קו"ח ופורטפוליו

## למה זה חשוב

אתם יכולים להיות המתכנתים הכי טובים בעולם, אבל אם קורות החיים שלכם נראים כמו מסמך Word משנת 2003 עם גופן Comic Sans -- אף אחד לא ידע את זה. הקו"ח והפורטפוליו הם **כרטיס הביקור** שלכם. הם קובעים אם תקבלו שיחת טלפון ראשונה או מייל דחייה אוטומטי.

> "שלחתי 50 קורות חיים ולא קיבלתי אף תשובה. שיניתי את הקו"ח לפי הטיפים שלמטה, ותוך שבוע קיבלתי 3 זימונים. הבעיה לא הייתה אני -- הבעיה הייתה הניירת."

!!! note "הכלל הראשון"
    ל-Recruiter יש בממוצע **6-10 שניות** לסרוק את הקו"ח שלכם. אם המידע החשוב לא קופץ לעין מיד -- עברתם לערימת ה-"לא".

---

## מה Recruiters באמת מחפשים

### ב-6 השניות הראשונות

1. **שם התפקיד שאתם מחפשים** -- "Junior Backend Developer" לא "מחפש הזדמנויות"
2. **טכנולוגיות רלוונטיות** -- Python, React, Docker -- מילות מפתח שתואמות למשרה
3. **ניסיון / פרויקטים** -- כמה שנים או אילו פרויקטים בנית
4. **השכלה** -- תואר רלוונטי או בוטקמפ מוכר

### מה באמת מרשים (ומה לא)

| מרשים | לא מרשים |
|-------|----------|
| פרויקט שרץ ב-production | "למדתי Python מ-YouTube" |
| תרומה ל-Open Source | רשימת 20 טכנולוגיות שנגעתם בהן פעם |
| בעיה שפתרתם ואיך | "מוטיבציה גבוהה ושחקן צוות" |
| מספרים (ביצועים, משתמשים) | משפטי כותרת כלליים |
| GitHub פעיל עם פרויקטים | GitHub ריק |

## מערכות ATS -- מה זה ולמה זה משנה

### מה זה ATS?

**Applicant Tracking System** -- תוכנה שסורקת את הקו"ח שלכם **לפני** שעין אנושית רואה אותם. רוב החברות הגדולות משתמשות ב-ATS (Greenhouse, Lever, Workday, Comeet).

!!! warning "אם ה-ATS לא אוהב את הקו"ח שלכם -- אף אחד לא יראה אותם"
    המערכת מחפשת **מילות מפתח** ומדרגת את ההתאמה שלכם למשרה. קו"ח יפים עם גרפיקה, טבלאות, ועמודות -- עלולים להישבר ב-ATS.

### איך לכתוב קו"ח שעוברים ATS

1. **השתמשו בפורמט פשוט** -- עמוד אחד, טקסט נקי, בלי טבלאות/גרפיקה מורכבות
2. **PDF (לא Word)** -- אלא אם ביקשו אחרת
3. **שלבו מילות מפתח מהמשרה** -- אם כתוב "Python, FastAPI, PostgreSQL" במודעה, וודאו שהן מופיעות בקו"ח
4. **אל תשתמשו בכותרות יצירתיות** -- "ניסיון" ולא "הרפתקאות המקודדות שלי"
5. **אל תשימו מידע חשוב ב-Header/Footer** -- חלק מה-ATS לא קוראים אותם

??? tip "איך לבדוק אם הקו"ח שלכם עוברים ATS?"
    1. העתיקו את הטקסט מה-PDF ללא עיצוב (Ctrl+A, Ctrl+C, Ctrl+V ל-Notepad)
    2. אם הטקסט קריא ומסודר -- ה-ATS יקרא אותו
    3. אם הטקסט מבולגן ולא בסדר הנכון -- צריך לתקן את המבנה

### המבנה המומלץ (עמוד אחד!)

```
┌────────────────────────────────────────────┐
│  שם מלא                                    │
│  Junior Backend Developer                   │
│  email | phone | linkedin | github          │
├────────────────────────────────────────────┤
│  SKILLS                                     │
│  Python, Flask, PostgreSQL, Docker, Git,    │
│  REST APIs, Linux, SQL                      │
├────────────────────────────────────────────┤
│  PROJECTS                                   │
│  ► Project Name (link)                      │
│    - What it does + tech stack              │
│    - Impact / metrics                       │
│  ► Project Name (link)                      │
│    - ...                                    │
├────────────────────────────────────────────┤
│  EXPERIENCE (if any)                        │
│  ► Role @ Company | dates                   │
│    - Achievement with numbers               │
│    - Achievement with numbers               │
├────────────────────────────────────────────┤
│  EDUCATION                                  │
│  ► Degree / Bootcamp | Institution | Year   │
├────────────────────────────────────────────┤
│  MILITARY SERVICE (relevant in Israel)      │
│  ► Role | Unit | dates                      │
└────────────────────────────────────────────┘
```

!!! note "כלל הזהב: עמוד אחד"
    אלא אם יש לכם 10+ שנות ניסיון, הקו"ח שלכם צריכים להיות **עמוד אחד**. Recruiter לא יקרא עמוד שני. אם זה לא נכנס -- תקצרו, אל תקטינו גופן.

### כללים לכתיבת תיאור ניסיון

**השתמשו בנוסחת XYZ של Google:**

> "Accomplished [X] as measured by [Y], by doing [Z]"

**דוגמאות:**

- **גרוע**: "עבדתי על פרויקט Backend"
- **בינוני**: "פיתחתי REST API ב-Python"
- **מצוין**: "פיתחתי REST API ב-Flask שמשרת 10K requests/day, כולל authentication ו-rate limiting, שהפחית את זמני התגובה ב-40%"

> "כל משפט בקו"ח שלכם צריך לענות על השאלה: 'אז מה? למה זה מרשים?' אם אין לכם תשובה -- תמחקו את המשפט."

## GitHub כפורטפוליו

### למה GitHub חשוב

GitHub הוא **ההוכחה** שאתם יודעים לכתוב קוד. Recruiter טכני (או מנהל הגיוס) **יכנס ל-GitHub שלכם**. מה שהוא/היא יראו שם משפיע מאוד.

### מה צריך להיות ב-GitHub

**פרופיל:**

- תמונה מקצועית (לא חובה, אבל עוזר)
- Bio קצר: "Backend Developer | Python | Building cool stuff"
- קישור לאתר אישי / LinkedIn

**Pinned Repositories (3-6 פרויקטים):**

כל פרויקט צריך:

1. **README מסודר** -- מה זה, screenshot/demo, איך להריץ
2. **קוד נקי** -- שמות משתנים ברורים, הערות במידה
3. **Commits מסודרים** -- "Fix login bug" ולא "asdfgh" או "stuff"
4. **הוספת Issues ו-Project Board** -- מראה על ארגון

!!! warning "GitHub Red Flags"
    דברים שגורמים לרושם רע:

    - Repositories ריקים או עם commit אחד
    - קוד שמועתק מ-tutorial בלי שינוי
    - שמות commits כמו "aaa", "fix", "update"
    - סיסמאות או API Keys בקוד (כן, זה קורה. השתמשו ב-.env!)
    - פרויקטים בלי README

??? tip "איך לבנות GitHub מרשים ב-30 יום?"
    **שבוע 1**: הכינו את הפרופיל, סדרו 2-3 פרויקטים קיימים עם READMEs

    **שבוע 2-3**: בנו פרויקט חדש אחד. commit כל יום (אפילו קטן)

    **שבוע 4**: תרמו ל-Open Source project (fix typo, improve docs, fix small bug)

    **בונוס**: הוסיפו GitHub Actions (CI/CD) לפרויקט. ראו [CI/CD](../04-systems/ci-cd.md)

## אתר אישי (Personal Website)

### למה כדאי

- **בולט** -- מפתח עם אתר אישי בולט מול 100 קורות חיים ב-PDF
- **מראה על יכולת** -- בנית אתר? הנה ההוכחה שאת/ה יודע/ת
- **שליטה מלאה** -- אתם מחליטים מה מופיע ואיך

### מה לכלול באתר

1. **About** -- מי אתם ומה אתם מחפשים (2-3 משפטים)
2. **Projects** -- 3-5 פרויקטים עם screenshots, tech stack, ולינקים
3. **Blog** (אופציונלי אבל מומלץ) -- כתבו על מה שלמדתם. אפילו פוסט אחד בחודש
4. **Contact** -- email, LinkedIn, GitHub
5. **Resume** -- לינק ל-PDF להורדה

### טכנולוגיות מומלצות

| מה | כלי | עלות |
|----|------|------|
| אתר סטטי פשוט | GitHub Pages + HTML/CSS | חינם |
| אתר מודרני | Next.js / Astro + Vercel | חינם |
| בלוג | Hugo / Gatsby / Hashnode | חינם |
| דומיין | Namecheap / Google Domains | ~$10/שנה |

> "האתר שלכם לא צריך להיות יצירת מופת. הוא צריך להיות נקי, מהיר, ולהראות שאתם יודעים מה אתם עושים. אל תבזבזו שבועיים על אנימציות -- תשקיעו בתוכן."

## LinkedIn -- ההזנחה הגדולה

### למה LinkedIn חשוב בישראל

רוב הגיוס ההייטקי בישראל **מתחיל ב-LinkedIn**. Recruiters מחפשים מועמדים באופן אקטיבי. אם הפרופיל שלכם חלש -- אתם **בלתי נראים**.

### אופטימיזציה של פרופיל LinkedIn

**Headline** (הכי חשוב!):

- **גרוע**: "מחפש/ת עבודה"
- **בינוני**: "Software Developer"
- **מצוין**: "Backend Developer | Python & Go | Building scalable APIs"

**About Section:**

- 3-4 פסקאות קצרות
- מה אתם עושים, מה מעניין אתכם, מה אתם מחפשים
- שלבו מילות מפתח טכניות (Recruiters מחפשים לפיהן)

**Experience:**

- כמו בקו"ח -- הישגים עם מספרים, לא רשימת משימות
- הוסיפו פרויקטים כ-"Experience" אם אין לכם ניסיון מקצועי

**Skills & Endorsements:**

- הוסיפו את כל הטכנולוגיות שאתם שולטים בהן
- בקשו endorsements מחברים/קולגות

!!! note "טיפ: היו פעילים"
    LinkedIn algorithm מעדיף אנשים פעילים. פרסמו פוסט פעם בשבוע-שבועיים:

    - מה למדתם השבוע
    - פרויקט שהשלמתם
    - מאמר מעניין שקראתם
    - שאלה טכנית ותשובה

    **זה לא אגו -- זה Marketing**. אם אתם לא מספרים לעולם מה אתם עושים, אף אחד לא ידע.

## Cover Letters -- האם זה עדיין רלוונטי?

### התשובה הקצרה: תלוי

| מתי כדאי | מתי לא צריך |
|----------|------------|
| חברה קטנה / סטארט-אפ | חברה גדולה עם ATS |
| המשרה ספציפית ואתם מתאימים מאוד | שליחה מסיבית של קו"ח |
| יש לכם סיפור מעניין לספר | המודעה לא מבקשת |
| הגשה דרך email ישיר | הגשה דרך פורטל חברה |

### אם כותבים -- ככה עושים את זה

**3 פסקאות, חצי עמוד, לא יותר:**

1. **פתיחה**: למה אתם פונים לחברה הזו ספציפית (לא "ראיתי משרה")
2. **גוף**: 2-3 דברים רלוונטיים שעשיתם שמתאימים למשרה
3. **סיום**: Call to action -- "אשמח לשוחח על איך אוכל לתרום ל-[X]"

> "Cover letter טוב הוא כמו trailer לסרט -- אם הוא מעניין, תרצו לראות את הסרט המלא (הקו"ח). אם הוא משעמם, אפילו סרט מצוין לא יעזור."

## טעויות נפוצות

!!! warning "הטעויות שפוגעות הכי הרבה"
    1. **שליחת אותו קו"ח לכל משרה** -- כל משרה צריכה version מותאם
    2. **רשימת טכנולוגיות בלי הקשר** -- "Python, Java, C++, Rust, Go, Haskell" אומר "נגעתי בהכל, לא מומחה בכלום"
    3. **אין מספרים** -- "שיפרתי ביצועים" < "שיפרתי זמני תגובה ב-60%"
    4. **שגיאות כתיב** -- במיוחד באנגלית. תשתמשו ב-Grammarly
    5. **GitHub ריק / לא מקושר** -- אם אין לכם GitHub -- בנו אחד עכשיו
    6. **תמונה לא מקצועית** -- selfie מהחוף לא מתאים ל-LinkedIn
    7. **יותר מדי עמודים** -- Junior? עמוד אחד. נקודה.
    8. **פורמט שנשבר** -- בדקו שה-PDF נראה טוב על מחשב אחר

## שאלות לראיון עבודה

??? tip "ספר/י לי על הפרויקט שעשית"
    **מה באמת שואלים**: האם באמת בנית את זה, והאם אתה מבין את ההחלטות הטכניות?

    **מבנה תשובה:**

    1. **מה הפרויקט עושה** (משפט אחד)
    2. **למה בחרת את הטכנולוגיות** (הסבר קצר)
    3. **מה היה האתגר הכי גדול** (וכיצד פתרת)
    4. **מה היית עושה אחרת היום** (מראה על למידה)

    תתכוננו שישאלו שאלות העמקה! אם כתבתם REST API -- תדעו להסביר למה REST ולא GraphQL.

??? tip "למה את/ה רוצה לעבוד אצלנו?"
    **מה באמת שואלים**: האם חקרת אותנו, או שלחת לכולם?

    תעשו מחקר **לפני** הראיון:

    - מה המוצר של החברה
    - באיזו טכנולוגיה הם משתמשים (בדקו ב-BuiltWith, Glassdoor, או GitHub שלהם)
    - חדשות אחרונות (גיוס כסף, מוצר חדש)

    **תשובה טובה**: "ראיתי שאתם עובדים עם Kubernetes ו-Go, שזה בדיוק מה שאני רוצה להעמיק בו. בנוסף, המוצר שלכם ב-[X] מעניין אותי כי [Y]."

??? tip "יש לך שאלות אלינו?"
    **מה באמת שואלים**: האם אכפת לך מספיק כדי להתכונן?

    **שאלות טובות לשאול:**

    - "איך נראה יום טיפוסי בתפקיד?"
    - "מה ה-tech stack ואיך הוא נבחר?"
    - "איך נראה תהליך ה-code review?"
    - "מהם האתגרים הגדולים שלכם השנה?"

    **שאלות לא לשאול (בראיון הראשון):**

    - "כמה חופש יש?" (תשאלו בשלב המשא ומתן)
    - "אפשר לעבוד מהבית?" (תשאלו בעדינות, לא כשאלה ראשונה)

??? tip "מה ה-gap בקו\"ח שלך?"
    **מה באמת שואלים**: האם יש משהו שצריך לדאוג ממנו?

    **עיקרון**: הסבירו בכנות ובקצרה, והדגישו מה עשיתם בזמן הזה.

    **דוגמה**: "לקחתי שנה ללימודים עצמיים אינטנסיביים ובניית פורטפוליו. בתקופה הזו סיימתי 3 פרויקטים ותרמתי ל-2 פרויקטי Open Source."

    **אל תתנצלו.** אל תשקרו. תסבירו ותמשיכו הלאה.

??? tip "מה הציפיות שלך לשכר?"
    **מה באמת שואלים**: האם אתה במסגרת התקציב שלנו?

    **עצות:**

    - חקרו שכר ממוצע באתרים כמו Glassdoor ו-LinkedIn Salary
    - תנו טווח ולא מספר בודד: "אני מצפה לטווח של X-Y"
    - אם אפשר -- דחו את השאלה: "אשמח לדון על זה אחרי שנבין טוב יותר את התפקיד"
    - **אל תגידו מספר ראשונים אם אתם יכולים להימנע**
